# AI Hub / HOPE full product completion plan

This plan is the scope lock for the final completion branch. Do not call the product complete merely because foundations exist. Each phase must ship its user-facing experience, backend behavior, tests and production validation where credentials permit.

## Phase 1 — Academy completion
- Beginner, Intermediate and Advanced curriculum with explicit prerequisites and progression.
- Searchable/categorized AI tools and model library, official links, free/paid/provider metadata and owner-updatable catalog.
- Major-tool lesson pages with what/why/when/not-to-use, practical workflow, examples and challenge.
- 60–90 second lesson-story content contract and media slots; voice narration with safe browser fallback and optional server voice provider.
- Fun quiz/challenge formats, adaptive difficulty, HOPE Tutor in lesson context, mastery and remediation.
- What's New in AI feed surface with owner-curated/manual fallback until a live feed source is configured.
- Skill Passport, Proof Arena, certification gates, completion evidence and retention/revision.
- Mobile/desktop accessibility and reduced-motion validation.

## Phase 2 — HOPE completion
- Preserve normal general-purpose GPT-style chat as the default.
- Persistent threads, user-controlled memory, projects/goals/world-state and clear delete/reset controls.
- Intent routing: answer normally; offer Academy or HYVORA transitions without forcing them.
- Cross-module handoff contracts and resumable missions.
- Voice input/output, mood modes, files/images, research and connector/action confirmations.
- HOPE Daily, opportunity/inbox surfaces and proactive suggestions only with user control.
- Autonomy levels, approval policy, Guardian review, evidence/assumption/confidence surfaces for consequential actions.
- Admin/Owner command center, provider budgets, emergency stop and usage visibility.

## Phase 3 — Themes and experience
- Restore and finish the discussed four scene families: Dragon Day, Dragon Night, AI Day, AI Night.
- AI Day/Night must be independently art-directed futuristic environments, not simple recolors or planet placeholders.
- Theme persists per user/device, works across HOPE/Academy/HYVORA shell, and honors reduced motion.
- Original product identity/logo treatment; no accidental third-party/placeholder branding.
- Responsive premium mobile + desktop navigation and consistent module shell.

## Phase 4 — HYVORA completion
- Brand Brain, campaign missions, strategy, content studio, repurposing, approvals and calendar.
- Media/asset library, reusable templates, captions/subtitles, hooks/CTA variants and batching.
- YouTube/Instagram/Facebook connector onboarding and server-only secret handling.
- Real provider publishing adapters only after OAuth/account permissions are present; explicit approval and owner enable gates.
- Real analytics ingestion, channel/campaign dashboards, winning-hook/content learning and next-action recommendations.
- Trend/competitor/topic research with source attribution when a live research source is configured.
- Low-cost video workflow first; optional paid generation providers behind owner toggles.
- Recorded-content/live-stream workflow only where platform policies and account permissions allow it; never promise monetization.

## Phase 5 — Cross-module intelligence
- HOPE can create/resume Academy learning missions and HYVORA campaigns from natural chat after confirmation.
- Academy progress can inform HOPE recommendations.
- HYVORA performance can create recommended Academy skills and HOPE follow-ups.
- Shared project/goal context with strict user isolation and transparent handoffs.

## Phase 6 — Plans, trials, referrals and credits
- Replace obsolete Free/Pro/Builder/Teams presentation with the agreed product/module packaging.
- General HOPE access separated from premium Academy/Marketing/Build entitlements.
- One 3-day premium-module trial policy.
- Referral reward: only after qualifying subscription; abuse-resistant ledger/job design.
- HOPE Credits/usage ledger and owner-configurable provider budgets.
- Payments remain non-transactional until a payment provider is explicitly connected and tested.

## Phase 7 — HOPE Build
- Isolated build workspace/execution boundary.
- Prompt → plan → build → test → repair → preview → version → deploy workflow.
- No arbitrary production mutation without confirmation; version/rollback support.
- Optional external builders/providers behind integrations rather than hard dependency.

## Phase 8 — Data/infrastructure completion
- Preserve working Cloudflare Pages + Functions + D1 while Supabase migration is verified.
- Import missing Supabase migration history, session adapter and dual-write verification before any cutover.
- RLS/user isolation, provider vault, entitlement consistency, backup/rollback and schema drift checks.
- Secrets remain server-side.

## Phase 9 — Full production audit
- Automated syntax/dependency/security/production gates.
- Multi-account isolation tests.
- Five-turn+ HOPE/mood regressions and memory reset tests.
- Academy progression, remediation, certification and retention tests.
- HYVORA generate → approve → schedule → publish → analytics → learn test with real accounts when credentials are supplied.
- Budget exhaustion, rate-limit, provider outage/fallback and emergency-stop tests.
- Mobile/desktop/accessibility/reduced-motion checks.
- Deployment + release stamp + rollback verification.
- Final owner-only checklist for credentials/OAuth/payment/domain/email/manual real-account verification.

## Completion rule
A phase is complete only when its planned product experience exists and its non-secret-dependent tests pass. Features requiring third-party credentials are complete-in-code only when adapters, validation, toggles and safe failure states exist; they are production-verified only after the owner supplies and authorizes the real account.
